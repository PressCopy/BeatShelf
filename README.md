# Beatshelf

Органайзер битов для тех, кто делает музыку в FL Studio и Ableton Live. Раскладывает экспорты и проекты по понятной структуре папок, хранит BPM, тональность, статусы и оценки, и ничего не делает с файлами без твоего подтверждения.

Статус: **MVP (0.4)**. Работает на Windows (x64, ARM64) и macOS (Apple Silicon, Intel). Лицензия MIT.

## Что умеет MVP

- **Онбординг в три шага:** папка библиотеки и папки DAW → шаблон структуры → предпросмотр дерева перед созданием.
- **Очередь сортировки.** Новые файлы из `00_Inbox` и из папок FL Studio и Ableton попадают в очередь, когда запись файла закончилась. Отмечаешь файлы одного бита и выбираешь «новый бит» или существующий. Приложение показывает план и выполняет его только после подтверждения.
- **Библиотека:**
  - разделы под «Библиотекой» в боковом меню: биты, лупы, стартеры, войстеги, у каждого счётчик;
  - список, который не тормозит на больших объёмах;
  - волна в каждой строке: клик запускает звук, клик по играющей волне перематывает;
  - поиск по названию, жанру, настроению, тональности и BPM;
  - фильтр по статусу;
  - правка полей прямо в строке: клик по выделенной строке.
- **Биты, лупы и стартеры.** Три типа с общими полями и плеером, у каждого свой раздел: `01_Beats`, `06_Loops_Starters/Loops`, `06_Loops_Starters/Starters`. Если сменить тип в карточке, она предложит перенести папку.
- **Войстеги.** Четвёртый тип со своим разделом `07_Voicetags`. В войстеге хранятся WAV, MP3 и проекты FL Studio и Ableton (`.flp`, Zipped loop package, `.als`, папка проекта Ableton). Файлы лежат прямо в его папке, без подпапок. Контракт, картинку или обычную папку приложение туда не положит: план покажет причину и не выполнится.
- **Обложки и скачивание MP3.** В карточке бита можно выбрать обложку (JPG, PNG, WebP). Она приводится к размеру до 1000 px и кладётся в `Artwork/cover.jpg`. Кнопка «Скачать MP3» сохраняет копию MP3 с обложкой, названием, авторами, BPM и тональностью в тегах и открывает папку с файлом, чтобы его можно было сразу отправить, например в Telegram.
- **Цвет бита.** По умолчанию бит окрашен по тональности (круг Camelot). В карточке можно выбрать свой цвет из палитры или любой другой; он используется на плитке в списке и на волне.
- **Авторы и соавторы.** Отдельные поля, по ним работает поиск. Своё продюсерское имя задаётся в настройках и подставляется автоматически. Из имени файла вида `Night (prod. maks x lowkey)` авторы читаются сами.
- **Карточка бита:**
  - все файлы бита, отметка самого свежего проекта, если он есть в обеих DAW;
  - кнопки «Добавить файлы» и «Добавить папку»: контракты попадают в `Contracts`, трекаут в `Stems_Trackouts`;
  - если имя папки разошлось с полями, её можно переименовать.
- **Перетаскивание:**
  - строку бита или файл из карточки можно утащить в FL Studio, Ableton, Telegram или письмо, файл всегда копируется;
  - файлы из Finder или Проводника можно бросить на бит или в окно, тогда приложение спросит, в какую подпапку их положить или отправить в Inbox;
  - оригиналы остаются на месте.
- **Редактор шаблонов имён** в настройках. Есть токены `{name}` `{bpm}` `{key}` `{camelot}` `{year}` `{date}` `{authors}` `{coauthors}` `{producers}` и живой пример. Часть в `[квадратных скобках]` пропадает, если внутри пусто: шаблон `{name}_{bpm}bpm_{key}[ (prod. {producers})]` даёт `Night_140bpm_Am (prod. maks x lowkey)`.
- **Плеер:**
  - волна в цвете тональности по кругу Camelot;
  - пробел, ← →, J/K/L;
  - волна считается в Rust один раз и кэшируется.
- **История с отменой.** Отмена тоже показывает план. Ctrl/⌘+Z отменяет последнее действие.
- **Интерфейс:** русский и английский, тёмная, светлая или системная тема, управление с клавиатуры.

## Безопасность файлов

Это главное, ради чего написано ядро (`crates/beatcore`), и всё ниже покрыто тестами, которые CI гоняет на Windows, macOS и Linux.

- **Только по подтверждённому плану.** Ничего не меняется без плана, который ты увидел. Перед выполнением план проверяется заново: если файлы успели измениться, он не выполнится.
- **Никакой перезаписи.** Совпадение имени с точностью до регистра или нормализации Unicode тоже считается занятым местом.
- **Откат при ошибке.** Если шаг упал посреди операции, уже сделанные шаги откатываются.
- **Файлы снаружи только копируются.** Перетащенные или выбранные в диалоге файлы копируются в библиотеку со сверкой хеша. Перенести файл снаружи нельзя, а отмена отправляет копию в корзину.
- **Перетаскивание из окна** всегда передаёт копию, принимающая программа не может забрать файл из библиотеки.
- **Скачивание MP3 не трогает библиотеку.** Теги пишутся в копию, файл в библиотеке только читается. Сохранить копию внутрь библиотеки или папки DAW нельзя.
- **Удаление только через корзину ОС.** Удаляются без корзины лишь пустые папки, которые создало само приложение.
- **Перенос между дисками** идёт по схеме: копия → сверка BLAKE3 → оригинал в корзину.
- **Проект Ableton переносится только целой папкой.** Если сет ссылается на сэмплы вне своей папки, приложение предупредит и посоветует сделать *Collect All and Save*.
- **Для `.flp`** приложение предупреждает, что внутри пути к сэмплам, и советует *Zipped loop package*.
- **Бэкапы и автосейвы** (`Backup/`, `(autosave)`, `(overwritten at …)`) в библиотеку не попадают.
- **Имена файлов** безопасны для Windows и macOS одновременно. Длинные пути (>259 символов) вызывают предупреждение, потому что их может не открыть FL Studio.

## Установка

Скачай файл для своей системы со страницы **Releases**. Сборки пока без подписи, поэтому система при первом запуске спросит, доверяешь ли ты приложению.

**Windows.** Запусти `Beatshelf_x.y.z_x64-setup.exe` (или `arm64`). Если появится «Windows защитила ваш компьютер», нажми «Подробнее» → «Выполнить в любом случае».

**macOS.** Открой `.dmg` и перетащи Beatshelf в «Программы». При первом запуске macOS скажет, что не может проверить разработчика. Дальше так:

1. Открой «Системные настройки» → «Конфиденциальность и безопасность».
2. Внизу у строки про Beatshelf нажми «Всё равно открыть».

Если macOS пишет, что приложение повреждено, выполни в Терминале:

```sh
xattr -dr com.apple.quarantine /Applications/Beatshelf.app
```

## Сборка релиза через GitHub

1. Залей репозиторий на GitHub.
2. Поставь тег версии и отправь его:
   ```sh
   git tag v0.1.0 && git push origin v0.1.0
   ```
3. Workflow **Release** соберёт macOS (универсальный: Apple Silicon + Intel), Windows x64 (MSI и NSIS) и Windows ARM64 (NSIS). Результат появится черновиком в Releases.
4. Проверь черновик и нажми «Publish».

Версия берётся из `src-tauri/tauri.conf.json`. Меняй её вместе с `package.json` и `Cargo.toml`.

Workflow **CI** на каждый push гоняет тесты ядра на трёх ОС и проверяет, что приложение собирается.

### Подпись (по желанию, позже)

- **macOS.** Нужен Apple Developer Program. Добавь сертификат и данные для нотаризации в секреты репозитория и раскомментируй переменные `APPLE_*` в `.github/workflows/release.yml`.
- **Windows.** Для open-source можно подать заявку в SignPath Foundation. Платная альтернатива — сертификат Certum для open-source разработчиков.

## Локальная разработка

Нужны Rust stable (1.85+) и Node.js 22. Дополнительно:

- **Windows:** Microsoft C++ Build Tools. WebView2 в Windows 10/11 уже есть.
- **macOS:** `xcode-select --install`.
- **Linux** (для разработки ядра): `libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev libsoup-3.0-dev`.

```sh
npm ci
npm run tauri dev      # приложение с горячей перезагрузкой
npm run tauri build    # установщик для текущей системы
cargo test -p beatcore # тесты ядра
```
