# Архитектура Beatshelf

## Слои

```
┌──────────────────────────── src/ (React, TypeScript) ────────────────────────────┐
│ экраны · плеер (wavesurfer.js) · окно плана · i18n · тема                         │
└──────────────── invoke(команда, ID) ▼            ▲ события (inbox-changed, …) ───┘
┌──────────────────────────── src-tauri/ (оболочка) ───────────────────────────────┐
│ commands.rs: ID → путь, проверка, план; watcher.rs: notify + стабилизация записи  │
└───────────────────────────────────────▼──────────────────────────────────────────┘
┌──────────────────────────── crates/beatcore/ (ядро) ─────────────────────────────┐
│ ops       план → проверка → выполнение → журнал → отмена                          │
│ daw       FL / Ableton / бэкапы / внешние сэмплы в .als                           │
│ template  структура папок и имена по токенам                                      │
│ parse     BPM и тональность из имени файла                                       │
│ keys      тональности и Camelot                                                   │
│ pathsafe  имена, безопасные для Windows и macOS                                   │
│ inbox     кандидаты в очередь, ожидание конца записи                              │
│ scan      пересчёт библиотеки                                                     │
│ audio     symphonia: длительность, формат, пики волны                             │
│ db        SQLite + FTS5                                                           │
└──────────────────────────────────────────────────────────────────────────────────┘
```

Ядро не зависит от Tauri. Поэтому вся логика файлов тестируется обычным `cargo test` на трёх ОС в CI, без окна и без вебвью.

## Правило границы

Интерфейс никогда не отправляет пути в команды, которые трогают диск. Он передаёт ID бита, файла, элемента очереди или плана. Rust сам находит путь и проверяет, что тот лежит внутри библиотеки или отслеживаемой папки DAW. Пути идут только из Rust в интерфейс: для показа и для аудиоплеера через asset protocol, область которого ограничена теми же папками.

## Модель безопасности файлов

1. **План.** `PlanBuilder` собирает шаги (`CreateDir`, `Move`, `Copy`, `Trash`, `RemoveEmptyDir`) и прогоняет их через виртуальную файловую систему. Каждый шаг проверяется против состояния, которое будет после предыдущих, а не против текущего диска. Нарушения делятся на блокеры (план нельзя выполнить) и предупреждения (можно, но стоит знать).
2. **Подтверждение.** План хранится в памяти по ID. Пользователь видит пути «было → станет» и предупреждения.
3. **Повторная проверка.** Прямо перед выполнением план проверяется ещё раз. Если диск изменился, выполнение отменяется, ничего не тронуто.
4. **Выполнение с журналом.** Каждая сделанная операция сразу пишется в таблицу `ops`. Если приложение упадёт посреди пакета, при следующем запуске он помечается как прерванный. Записанные шаги остаются в журнале, поэтому сделанное можно отменить.
5. **Откат.** Если шаг упал, уже сделанные шаги откатываются в обратном порядке.
6. **Отмена.** Обратный план строится из журнала и показывается как обычный план.

Инварианты, которые проверяют тесты (`crates/beatcore/tests/file_safety.rs`):

- запись никогда не перезаписывает существующий файл, даже если имя отличается только регистром или нормализацией Unicode;
- удаление идёт только через корзину ОС; без корзины удаляются лишь пустые папки, созданные этим приложением, и его собственные временные копии;
- `.als` нельзя отделить от папки проекта Ableton;
- перенос между дисками: копия во временное имя → сверка BLAKE3 → атомарное переименование → оригинал в корзину;
- переименование, меняющее только регистр, идёт через временное имя, иначе оно не сработает на APFS и NTFS;
- после создания библиотеки и отмены не остаётся ни одной папки;
- `Copy` берёт источник откуда угодно, но пишет только внутрь библиотеки. Оригинал не трогается, отмена отправляет копию в корзину. `Move` снаружи по-прежнему запрещён.

## Файлы снаружи: перетаскивание и выбор

Перетаскивание на окно ловит Rust (`WindowEvent::DragDrop`). Пути остаются в `AppState.drops` под случайным ID. Интерфейс получает ID, имена файлов, догадку о подпапке и координаты, а по координатам находит бит под курсором (`data-beat-id`). Диалог «Добавить файлы» тоже открывается в Rust. Кнопка «Добавить папку» (`pick_import`) работает так же: содержимое выбранной папки становится файлами одного нового элемента (проект Ableton берётся целиком), а имя папки разбирается на название, BPM и тональность. Папку внутри библиотеки выбрать нельзя. Так правило «пути не приходят из интерфейса» сохраняется и для файлов извне.

Перетаскивание наружу делает крейт `drag`. Команда `start_drag` получает ID файла или бита, сама находит путь и всегда запускает копирование (`DragMode::Copy`). Пока идёт наше перетаскивание, окно игнорирует собственный drop.

## Типы элементов и авторы

`beats.kind` ∈ `beat | loop | starter | voicetag`. У каждого типа свой шаблон папки (`beatDir`, `loopDir`, `starterDir`, `voicetagDir`).

Войстег (`voicetag`) — «плоский» тип: файлы лежат прямо в его папке, и принимаются только аудио WAV и MP3 и проекты DAW: `.flp`, Zipped loop package, `.als` и папка проекта Ableton (`ItemKind::accepts` смотрит на вид файла, `AssetKind`). Это правило библиотеки, а не состояние диска, поэтому оно оформлено как отдельный блокер плана (`IssueCode::VoicetagFileType`, `PlanBuilder::block`): шаг для такого файла в план не попадает, а `execute` отказывается выполнять план с таким блокером. Сменить тип существующего элемента на войстег нельзя, пока в нём есть что-то ещё: контракт, обложка, обычная папка.

## Обложки, цвет и скачивание MP3

Обложка бита — картинка `cover.*` в его папке. Отдельного поля в базе нет: запрос списка сам находит такой файл среди файлов бита, поэтому обложка переживает переименование и перенос папки. Выбранная картинка сначала приводится к JPEG до 1000 px (`cover::normalized_cover`) и ждёт в кэше приложения, а в библиотеку попадает обычным планом: старая обложка уходит в корзину, новая копируется на её место.

«Скачать MP3» (`cover::export_mp3`) не относится к операциям с библиотекой и идёт мимо планов. Исходный MP3 только читается. Копия создаётся под временным именем рядом с местом назначения, в неё пишутся теги ID3v2.3 (название, авторы, BPM, тональность, жанр, обложка), и в конце она переименовывается. Сбой не оставляет после себя файлов. Место выбирает пользователь в системном диалоге; путь внутри библиотеки или папок DAW отклоняется, чтобы библиотека менялась только через планы. WAV так пометить нельзя, а кодировщика MP3 в приложении нет, поэтому функция работает с уже экспортированными MP3.

Цвет бита хранится в `beats.color` как `#rrggbb` (команда принимает только такой формат, потому что значение попадает в стили интерфейса). Пустое поле означает цвет по тональности. Сканер находит элементы по статическому префиксу и глубине шаблона и при этом знает тип. Структуру раздела (префикс и глубину) нельзя менять, пока в нём есть элементы, иначе сканер их потеряет. Имя последней папки менять можно, старые папки получат кнопку «переименовать».

Пустой элемент (кнопка «Создать папку») — это строка в базе без папки на диске: `beats.draft = 1`, `folder = NULL`. Так сохраняется принцип «сначала виртуальная библиотека»: создание пустой папки ничего не меняет на диске и не требует плана. Когда в такой элемент добавляют первые файлы, `existing_target` выводит название из имени первого файла (`beats.auto_name = 1`, пока название не ввели вручную), вычисляет папку по шаблону и добавляет её создание в тот же план, что и копирование файлов. После выполнения строка получает папку и становится обычным элементом. Пустой элемент можно удалить; элемент с папкой так удалить нельзя.

Удаление элемента (`plan_delete_item`) — обычный план с одним шагом `Trash` для папки элемента и предупреждением `DeletesFiles` с числом файлов. Строка в базе исчезает сама: после выполнения библиотека перечитывает папку, не находит её и убирает элемент. Перед выполнением плеер отпускает файл элемента, иначе Windows не даст переместить его в корзину.

Авторы и соавторы хранятся строками `"maks, lowkey"` и попадают в полнотекстовый поиск. Миграция v1 → v2 пересоздаёт FTS-индекс и покрыта тестом.

## Данные

Одна база SQLite в папке данных приложения:

- `settings` — конфигурация: корень, шаблон, папки DAW, язык, тема;
- `beats` — поля бита, введённые вручную;
- `assets` — файлы бита с технической информацией и кэшем пиков волны. Пути внутри библиотеки хранятся относительно корня, поэтому папку библиотеки можно перенести целиком;
- `inbox` — очередь сортировки;
- `batches` и `ops` — журнал операций;
- `beats_fts` — полнотекстовый поиск. Буквы «ё» и «е» в нём не различаются.

## Слежение за папками

`notify` присылает события и только называет кандидатов. Файл попадает в очередь, когда его размер и время изменения перестали меняться: FL пишет рендер постепенно. Для папок DAW в очередь идёт только то, что изменилось после добавления папки, чтобы старые проекты не завалили очередь. Проект Ableton попадает в очередь целой папкой.

## Отступления от исходного ТЗ и почему

- **Волна.** wavesurfer.js работает только в основном плеере. Пики (1000 точек) считает Rust один раз и хранит в базе. Сотня тысяч экземпляров wavesurfer в списке не выдержала бы, а с готовыми пиками плееру не нужно декодировать файл в JS. Волны в строках списка рисуются из того же кэша как SVG (64 столбика). Запросы идут пачками и только для видимых строк; файл, увиденный впервые, декодируется один раз в фоне.
- **Стекло.** В MVP размыт только фон под диалогами. Mica и Liquid Glass пойдут в v1: плагин Liquid Glass для Tauri молодой и требует `macOSPrivateApi`, поэтому он будет надстройкой с запасным вариантом.
- **Интерфейс.** Раскладка в жанре браузера сэмплов: почти чёрный фон, один синий акцент, строки с обложкой-кнопкой Play, тегами и волной, поиск и фильтры пилюлями. Это собственный дизайн по мотивам жанра, а не копия чужого приложения: цвет по-прежнему несёт тональность (круг Camelot).
- **Фокус.** Обводка фокуса показывается только при навигации клавишей Tab и в нейтральном цвете; при работе мышью её нет.
- **Подпись.** Сборки без подписи. Для Apple Silicon используется ad-hoc подпись (`signingIdentity: "-"`), без неё скачанное приложение вообще не откроется. Переменные для полной подписи уже есть в release.yml.
- **Тональность.** Только то, что ввёл пользователь или что есть в имени файла, без анализа аудио, как в ТЗ. Нераспознанная тональность отклоняется с подсказкой, а не стирает старое значение.

## Что взяли у аналогов

- **Unshuffle:** виртуальная библиотека отделена от операций с файлами, структура строится после подтверждения. Его слабость — сборки без подписи. У нас она тоже есть, поэтому в README подробно описано, как пройти предупреждения.
- **ADSR и Sononym:** хорошо ищут сэмплы, но не ведут проекты и продажи. Наша ниша — биты как единица работы: версии в двух DAW, статусы, история.
- **BeatForge (prodbyeagle):** делает ставку на автоанализ. Мы сознательно его не делаем.

- Карточка бита: «Открыть в FL Studio / Ableton».

- Дубликаты по аудио-отпечатку (`rusty-chromaprint`, чистый Rust, MIT).
